# Worksheet design: generated, printable, provably right

How to make a standards-aligned sheet that a teacher trusts on sight and a photocopier can't ruin. Distilled from Mathness (a 2026 rebuild, K–5) and its v1 predecessor (K–8, react-pdf, abandoned): the rebuild kept v1's correctness ideas and dropped its renderer and its taxonomy-first build. Every rule carries the failure it prevents.

## The model: four parts

- **Skill**: the math for one standard. It offers **activities** (`make({ rng, level, theme }) → section`) and a **plan**, the activity ids in page order that make the default one-page sheet. A plan entry can be a list of **alternatives**; the seed picks one.
- **Block**: one way to draw a section (fact row, ten frame, number line, clock, maze, decoder). A renderer, a `height(data)` in points, a `check(data)` that re-derives every answer, an optional `trim` (one row fewer) and `grows` (takes spare height). Math lives in skills, drawing in blocks; a new skill reuses or extends a block before adding one.
- **Theme**: title, story line, hero art, four or more countable **objects**, optional slots (maze tiles, a schedule, pizza toppings). Activities declare what they need; a theme is offered for a skill only if it can dress every planned activity.
- **Composer**: recipe (`skill, theme, seed, level, pages, locks, skip`) → sections plus a page-fill estimate.

Section **roles** make the page a lesson: warm-up → practice → visual → puzzle → story → challenge.

**Build order.** Hand-make two or three showcase sheets to the quality bar first (Mathness: grade 1 pond addition, grade 2 zoo clocks, grade 4 pizza fractions), then pull the engine out of them. v1 went taxonomy-first (136 topics → 76 generator families → 28 archetypes, every preset specified) and produced generic drill grids before it produced one good page.

## Correctness

- **Answers are computed, never typed.** A typed key drifts from its problems, and one wrong key costs a teacher's trust for good. Story problems compute the answer and a one-line "why" from the same numbers.
- **Every block re-derives its answers independently.** `check` recomputes from the data a child sees, through an exact evaluator: bigint rationals so 0.1 + 0.2 = 0.3, fractions, mixed numbers, brackets, braces, thousands commas, superscripts; it throws on anything else, so a malformed equation fails its check instead of passing it. **Independence trap:** v1's circle-area generator and its check imported the same function, so the check compared a function with itself. A check shares no code with the generator. Check the drawing, not the intent: v1's clock check read the time back off the hand angles.
- **Check the promise, not just the arithmetic.** A maze has exactly one route and its wrong tiles are near misses (target ± 1, ± 2) so guessing fails; a decoder gives each letter its own number and adds decoys so a wrong answer spells a wrong letter; clock times are real five-minute times; a compare row has no ties unless equality is the point; a rounding item is never already round; a fraction drill never has a whole-number answer (4/4 marked "wrong" either way). Keep tests to promise checks like these.
- **No repeated problems.** Two identical items in one section, or a repeat of an earlier draw on the page, makes the composer redraw from the next stream (up to 12 times, keeping the draw with fewest repeats); the test suite fails on any repeat. "Identical" is semantic: 3 × 4 and 4 × 3 are one fact when turnarounds are the point; the same story about a different name is the same problem; two stories on the same product read as one. An activity whose repeats are the point says so (`repeats: true`).
- **Sample-space starvation is the likeliest real failure.** A tight level (sums to 20, addends ≥ 5, always crossing ten) can admit fewer distinct problems than the page asks for. Assert distinct-problems ≥ items needed **per level**, not per generator; keep counts low and deal small pools in shuffled rounds.
- **Seeded determinism.** Same link, same sheet. Give every activity its own rng stream (`seed/skill/activity`; `/draw` for redraws, `seed~2` for page 2, `seed/plan/i` for picking an alternative) so changing one section never reshuffles another, and a lock can pin one section while the rest reroll. Every hand-drawn mark carries an explicit seed: **roughjs treats seed 0 as random**, so the same sheet would print differently twice and build-time renders would never cache. Accept that editing a generator can drift an old link's numbers; versioning every link against your own fixes costs more.

## Print

- **Points, not pixels; one renderer.** The page is US Letter, 612 × 792pt, in plain CSS; SVG art at 1 unit = 1pt, so SVG `font-size` in px is pt on paper. The on-screen page is the printed page: print is the browser's dialog with `@page { size: letter; margin: 0 }`, and server PDFs are Chrome printing those same pages. v1's react-pdf cost ~480 KB gzipped, ran on the main thread, had no grid or table layout, and its built-in fonts mis-encode glyphs (`≤` in Helvetica prints `d`), and previews needed a second renderer. A4 keeps the same content box and changes only margins, so fit math holds.
- **Black-and-white first.** Most sheets are photocopied. Tints resolve to paper white unless the viewer turns colour on; dark areas are hatching, never solid grey; nothing a child reads depends on colour. Red is the key's pen only. One pen weight everywhere, scaled so a 100-unit frog printed at 60pt keeps the same line. Wobble the decoration, never the measurement: a clock's rim is hand-drawn, its ticks, numerals and hands are exact.
- **The key is the same page, marked up.** Render the sheet once per mode; answer marks (box, blank, bubble for < > =, ring, choice, pen, one-line why) show red only in key mode, in the spot the child writes. Rings are √2 the size of what they circle so corners clear; boxes widen per digit. A key that overlays the sheet can never drift from its layout and grades fastest.
- **Fill 70–95% of the page, measured.** Estimate fill from block heights + headings + gaps against the measured body height (Mathness: 638pt body, 10pt gaps); aim for 85–95%. Block heights are calibrated against the rendered page: after any layout change, measure real section heights and update `height`, or the fit test means nothing. Tests see heights only, so also sweep every sheet in a real browser for overflow (width included). Spare room up to ~34pt spreads between sections; past that it stays at the bottom, so a short sheet reads as ending, not as a hole.
- **Sizes by age.** Body/answer type: pre-K 15/24pt, K–2 13/17pt, 3–5 11.5/13pt. Countable pictures print at **20pt or more**: smaller, an apple, a ball and a ladybug are the same blob. Pictures shrink only when a section is down to one row, never below a floor (protractor 180pt, 10 × 10 grid 170pt, labelled figures 90pt). Titles fit one line beside Name and Date (~24 characters).
- **Typography.** A real minus (U+2212), a digit face with a plain oval zero, shapes (○ □ △ ✓) drawn as SVG rather than font glyphs. Child-friendly faces: Andika (body), Grandstander (titles), Caveat (a classmate's handwriting to mark, in pencil grey).
- **Decoration never looks like math.** No little crosses (read as +), dashes (−), dots in a row, or arrow points next to numbers; keep strokes out of where text sits (clock hands stop short of the numerals, lily-pad veins stay at the rim, maze tile craters sit where a rotated tile can't put them under a fact). Where geometry varies with data, test all legal values for collisions (v1 swept hand reach against the numeral ring at every legal angle; dot-to-dot fails any number within 3.2 units of a line, dot or number).
- **Look at every illustration.** New or changed art is printed to PDF, rasterised and inspected (student and key pages, several seeds, every level). Screens hide what paper shows; this caught clock numerals crowding ticks (v1's top complaint) and lily-pad veins crossing a +. A read-only critic subagent works well here: cohesion, clarity (collisions, clipped labels), handwriting room, balance, print realism (hairlines, grey that washes out). It also lists what renders well, so the fix pass doesn't regress it.

## Levels and the ramp

Three levels, **gentle / core / stretch**, core the default. Inside a sheet, warm-ups draw one level easier and challenges one harder, so every page ramps.

v1's calibration contract, the best written version:

- **easy**: the grade's floor, scaffold on, one structure; doable the day the skill is taught. **medium**: grade-typical, scaffold off. **hard**: the grade's ceiling plus one structural wrinkle (regrouping across zero, an interior blank, the unknown in a non-final position, "list all").
- Four axes, in order: magnitude → structure → scaffold → answer space. Each is non-decreasing from easy to hard; no level lowers one axis to buy room on another.
- **Grade-ceiling rule:** hard stays inside the standard. Where the standard caps scope (3.NF.A.3d same numerator or denominator only; 4.NBT.B.5 up to 4-digit × 1-digit and 2-digit × 2-digit; 5.OA.A.1 no exponents), hard escalates on scaffold or answer space instead of size.
- Levels vary parameters, never the shape of the activity: three shapes read as three skills. A same-named topic in two grades is two topics with two calibrations.
- Comparisons: define "close" in units of the leading place, and plan equalities in (v1: one in six; a sheet that never shows one teaches the wrong thing). Hold story-problem reading level near grade level; it isn't a difficulty axis.

## What goes on a sheet

- **Representations the wording asks for.** Read each standard's verbs and nouns, not just its topic: "with a letter standing for the unknown" (3.OA.D.8), "decompose a fraction into a sum" (4.NF.B.3b), "illustrate and explain … using equations, rectangular arrays, and/or area models" (4.NBT.B.5/6), "draw", "explain", "relative sizes of units" (4.MD.A.1), named position words (K.G.A.1). A symbols-only sheet for a "use a model" standard is a partial fit.
- **Activity kinds** (v1's 28 archetypes): expression, equation, vertical computation, long division, word problem, comparison, ordering, list answer, choice (true/false, select all), sort into bins, table fill, sequence; object sets, base-ten and ten frames, number bonds, number lines and rulers, fraction models (bar, circle, set), clocks, plane figures, angles, solids, nets, coordinate grids, picture graphs, bar graphs, line plots; scatter plots, compare-representations.
- **Story problems** cover every unknown position (result, change, start) and compare stories ("more than" and "times as many" side by side); ×/÷ kinds: equal groups, arrays, sharing, how many groups, times as many, leftovers, round up. Numbers fit the structure (parts ≥ a minimum, answers positive). Repeat names; skip pronouns.
- **Puzzles wrap any problem maker** whose answer is a number (hop maze, riddle decoder, colour-by-answer mosaic, cross-number for grade 3+), so every skill can have one.
- **Mark-the-work rows**: a classmate's solution in pencil grey, sometimes right, sometimes a classic slip; true/false equations about half true, "fix it by changing one number" found by search.
- **Several right answers** (decompose a fraction, draw a shape from clues): the key shows one model answer and the check accepts any.
- **Answer space sized to the answer**: a bubble for a symbol, a line for a name, room for every digit (a 7-year-old writing "10:25" needs more than 90pt).
- **No giveaway words**: a sorting row that says "puts in" tells the child it's a deposit; "saves $3 of gift money" doesn't.
- **Specific contexts beat generic ones**: "Nonna's 8-slice pizza", not "Ana has 6 marbles". The same prompt eight times down a page (v1's "What time is it?") reads as machine-made.

## Validation that needs people

The rebuild's blueprint (27 Sep 2026) set goals measured by people: a teacher can't reliably pick generated sheets from five teacher-made ones (blind test); a parent goes from landing to printing in under 30 s; a teacher builds a three-skill review in under 2 min; a 4th grader marks a 20-problem sheet with the key in under 2 min; teachers review inferred state and curriculum mappings; real parents read the guides. As of 2026-10-01 none had been run: every review so far was by agents. Report agent reviews as agent reviews, never as user validation.

## Teacher features that are really engine design

- **Spiral review**: a mix is 2–3 skills from one grade (K–2) or 2–4 (grades 3–5), one section per skill, shuffled by the seed, trimmed a row at a time, topped up in turns while ≤ 97% full; every section prints its standard as a chip. Refuse the rare mix that can't fit. The skills must share a grade in some set.
- **Page mix**: puzzles or story problems can be left off; plain practice is redrawn on its own stream to fill, avoiding problems already on the page. A page of only skippable sections keeps them.
- **Class sets**: 2–26 versions, version A is the sheet, version i uses seed `<seed>v<letter>`; locked sections hold across versions; every version's sheets print, then every key. Test that versions A–D differ.
- **Remix code + QR**: the footer prints the whole recipe as a short code (standard + theme + level + pages + skips + seed + locks) and a QR of the code's URL in upper case (QR alphanumeric mode keeps it 25–29 modules, scannable on a laser print). Seeds skip 0/o/1/l/i so codes can be typed back. Paper leads back to its key and to fresh variants.
- **Parent guide** printed after the key, written for the parent at the kitchen table and the teacher handing the sheet out (~110 words per skill): what it practises; one of the sheet's own problems worked (drawn from the same seed in key mode); 3–5 words to know, defined in a child's words; 2–3 mistakes specific enough to spot on the sheet ("adding the equal groups, 8 + 4, instead of multiplying"); the standards before and after, in the viewer's set; one tip for home, two sentences at most, with everyday objects. Describe the idea and the checks, not one required method ("your child's class may show another way"). Weak advice misleads a parent for a whole topic, where a weak problem costs one answer: review every guide, and pilot with real readers. Test length limits. Standards are named by code, never quoted; no curriculum name ever prints.
- **Drills** (plain practice outside the standards): one instruction, numbered problems, the key laid out the same; no theme or ramp; the grade shows on cards, never on paper. Counts stay low on purpose (facts 24/30 for K–1, 30/45 above; column math 12/16; long division 6/9). Small pools deal in shuffled rounds, never twice in a row; big spaces draw all-different and page 2 avoids page 1.
- **What the URL holds**: the problem set (skill, theme, seed, level, pages, locks, skips). Key on/off, colour, paper size and name lines are the printer's local settings, not the link.

## Test suite pattern

One test composes every skill × theme × level × many seeds (Mathness: 60) and asserts: rng deterministic; same recipe → same data; URL and remix code round-trip (pages, locks, skips, mixes); a locked section survives a reroll; every sheet estimates ≤ 100%; no repeated problem; page mixes still fit; every `check` empty; each skill's promises; random spiral mixes per grade fit and check out. Beside it: versions differ, guides fit and their examples check, drills re-derive and fit, **every standard in every set has a sheet**. Failure messages carry the exact seed to replay. Then a real-browser overflow sweep and the rasterised art audit for what tests can't see.
